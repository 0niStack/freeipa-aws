# Configuration

## `.env` variables

| Variable | Example | Description |
|---|---|---|
| `IPA_DOMAIN` | `corp.example.com` | DNS domain of the realm. Do not use `.local` |
| `IPA_REALM` | `CORP.EXAMPLE.COM` | Kerberos realm, the domain in uppercase |
| `IPA_HOSTNAME` | `ipa.corp.example.com` | Server FQDN. Must be inside `IPA_DOMAIN` |
| `IPA_IP` | *(empty)* | Private IP of the host. Auto-detected by `setup.sh` when empty |
| `IPA_ADMIN_PASSWORD` | `CHANGE_ME` | Admin password. Generated by `setup.sh` when left as `CHANGE_ME` |
| `IPA_DM_PASSWORD` | `CHANGE_ME` | Directory Manager password generated by `setup.sh` (see note below) |
| `IPA_FORWARDER` | `169.254.169.253` | Upstream DNS server for names outside the domain. Defaults to the AWS resolver when unset |
| `IPA_IMAGE` | `freeipa/freeipa-server:rocky-9` | Container image and tag |

> **Note on passwords:** the compose file passes only `PASSWORD` (set from `IPA_ADMIN_PASSWORD`) to the
> container. `IPA_DM_PASSWORD` is generated and stored in `.env` but is not passed to the container
> in this version. If you need a separate Directory Manager password, pass it explicitly with
> `--ds-password` in the installer command.

`.env` is created with mode 600 and listed in `.gitignore`. Never commit it.

## `docker-compose.yml` explained

```yaml
services:
  freeipa:
    image: ${IPA_IMAGE:-freeipa/freeipa-server:rocky-9}
    container_name: freeipa
    hostname: ${IPA_HOSTNAME}
    restart: unless-stopped
    stdin_open: true
    tty: true
    cgroup: host
    dns:
      - 127.0.0.1
    environment:
      PASSWORD: ${IPA_ADMIN_PASSWORD}
      IPA_SERVER_IP: ${IPA_IP}
    command: >
      ipa-server-install -U
      --domain=${IPA_DOMAIN}
      --realm=${IPA_REALM}
      --setup-dns
      --forwarder=${IPA_FORWARDER:-169.254.169.253}
      --no-reverse
      --no-ntp
      --skip-mem-check
    sysctls:
      net.ipv6.conf.all.disable_ipv6: 0
      net.ipv6.conf.lo.disable_ipv6: 0
    volumes:
      - ./data:/data
      - /sys/fs/cgroup:/sys/fs/cgroup:rw
    ports:
      - "${IPA_IP}:53:53/udp"
      - "${IPA_IP}:53:53/tcp"
      - "${IPA_IP}:80:80/tcp"
      - "${IPA_IP}:443:443/tcp"
      - "${IPA_IP}:389:389/tcp"
      - "${IPA_IP}:636:636/tcp"
      - "${IPA_IP}:88:88/tcp"
      - "${IPA_IP}:88:88/udp"
      - "${IPA_IP}:464:464/tcp"
      - "${IPA_IP}:464:464/udp"
```

| Setting | Why it is there |
|---|---|
| `hostname` | The container hostname must equal the FQDN, or the installer fails the hostname check |
| `cgroup: host` + `/sys/fs/cgroup:rw` | systemd inside the container needs a writable cgroup tree. Without both you get `Failed to create /init.scope control group` |
| `dns: 127.0.0.1` | The server must resolve names through its own DNS service while installing |
| `PASSWORD` | Admin password read by the image's entrypoint |
| `IPA_SERVER_IP` | The address the server registers in DNS (needed with `--setup-dns`) |
| `--setup-dns` | Run the integrated DNS server |
| `--forwarder` | Upstream resolver. Empty value breaks the command, so a default is provided |
| `--no-reverse` | Do not create reverse zones |
| `--no-ntp` | Time comes from AWS Time Sync |
| `--skip-mem-check` | The built-in memory check cannot read cgroup v2 in a container. Make sure the host has at least 2 GB available |
| `sysctls` | Keeps IPv6 enabled on the loopback interface, which IPA expects |
| `./data:/data` | Persistent state |
| ports on `${IPA_IP}` | Avoids the clash with `systemd-resolved` on port 53 |

`privileged: true` is **not** supported by the image and should not be used.

## Changing the image

Set `IPA_IMAGE` in `.env`, for example `freeipa/freeipa-server:rocky-9`. Back up `./data` before changing
tags. See [operations.md](operations.md).
